# 使用指南

[English](USER-GUIDE.en.md) · [简体中文](USER-GUIDE.md)

适用版本：插件 **0.1.4**，Super Productivity **19.1.0 或更新的 Windows 桌面版**。插件安装在 Super Productivity 中，Obsidian 无需额外安装插件。

## 1. 下载与安装

1. 从仓库的 [v0.1.4 安装包目录](https://github.com/Talentjoe/Super-Productive-Obsidian-Converter/tree/main/releases/v0.1.4)下载 `sp-obsidian-sync.zip`。也可以按 [Git 与开发指南](GIT-GUIDE.md)从源码构建。
2. 打开 Super Productivity 的“设置 → 插件”，选择／上传 ZIP，然后启用 **Obsidian Vault Sync**。
3. 主程序询问 Node 文件访问权限时选择允许。这是读取和写入 vault 所需的官方桌面接口。
4. 打开侧栏“Obsidian Sync / Obsidian 同步”。升级时重新上传新版 ZIP，关闭原面板后再打开；现有配置和同步目录继续使用。

安装的 ZIP 是完整插件。单独在浏览器打开 `index.html` 只能看到安装提示，不能同步。

## 2. 第一次连接 vault

1. 点击“选择文件夹”，选择 Obsidian **vault 根目录**，例如 `D:\Notes\MyVault`。也可直接输入完整路径。不要选择 vault 内已经生成的 `Super Productivity/` 子目录。
2. 在目录浏览器中可进入子目录或点击“↑ 上一级”；等目录读取完成后点击“使用此文件夹”。
3. 勾选要同步的项目。可以同时选择多个项目；需要同步 Inbox 时也勾选 **Inbox**。
4. 确认“具体时间使用的时区”。默认本机时区；可以使用 `Asia/Shanghai`、`America/Los_Angeles` 等 IANA 名称。
5. 保持“导出原生项目笔记”“导出历史归档”关闭，先完成基础同步。
6. 点击“保存设置”。如果面板显示“已暂停”，先点击“恢复同步”，再点击“立即同步”。
7. 检查“待处理问题”，然后在 Obsidian 打开 `Super Productivity/index.md`。它链接到各项目、标签、日历和 AI 编辑指南。

首次同步会合并两边已有内容，不根据标题合并同名任务，也不会因为 Markdown 没有某个任务就删除应用内容。新增行会自动获得身份标记。

### 中英文切换

在“语言 / Language”选择 English 或简体中文，再保存设置。可先只保存语言，再连接 vault。界面即时切换；下一次成功同步后，托管 notes 链接、索引区块和同步目录 AI 指南使用所选语言。英文链接显示 `notes`，中文显示“笔记”；两种别名和旧格式都继续兼容。任务 ID、note 路径、YAML、正文及用户标题／标签保留；已有生成区块外的标题不会强制翻译。

## 3. 同步目录

```text
Super Productivity/
├── README.md                    # 随插件更新的 AI 编辑指南
├── index.md                     # 根索引
├── projects/<项目名>--<稳定ID>/
│   ├── index.md                  # 项目索引
│   ├── tasks.md                  # 任务编辑入口
│   ├── task-notes/<任务ID>.md    # 每个任务的 notes
│   ├── project-notes/            # 开启项目笔记导出后生成
│   └── archive/YYYY-MM.md       # 开启历史归档导出后生成
├── tags/                        # 标签索引
├── calendar/                    # 日历索引与每日笔记
└── .sp-sync/                    # 内部状态、备份与移除副本
```

项目绑定后目录名保持稳定；改项目名称请在应用或 `tasks.md` 的 YAML 中操作。根／项目／标签／日历索引的生成区块为只读；生成区块之外的用户正文会保留。

## 4. 日常编辑任务

在已选择项目的 `tasks.md` 中新增：

```markdown
- [ ] 编写需求说明 #工作 ⏳ 2026-10-03 📅 2026-10-05 estimate [60min](<sp-estimate-minutes:: 60>)
- [ ] 准备演示
  - [ ] 整理资料 estimate [30min](<sp-estimate-minutes:: 30>)
```

新增行不填写已有 ID，成功同步后插件会写入 `<!-- sp:task:... -->`、`^sp-...` 和 `[[完整路径|笔记]]`。已有任务修改时保留这些标记。任务身份由 ID 决定，同名任务可以共存。

| 操作 | 编辑方式 |
| --- | --- |
| 改标题 | 修改复选框后的任务名称 |
| 完成／重新打开 | `[ ]` 与 `[x]` 切换 |
| 改独立任务标签 | 修改 `#工作` 等标签；特殊名称使用标签索引中的别名 |
| 改预计耗时 | 同时修改 `60min` 和 `sp-estimate-minutes:: 60` 的数值 |
| 改计划日期 | `⏳ YYYY-MM-DD` |
| 改截止日期 | `📅 YYYY-MM-DD` |
| 调整顺序 | 移动整条任务行，父任务和子任务保持在一起 |
| 改 notes | 点击“笔记”，编辑相应 `task-notes/*.md` 的正文 |

只支持父任务和一层子任务，新增子任务缩进两个空格。已有子任务可以保留原生独立标签，文件中的子任务标签为只读导出；如需改标签，在应用中操作。有子任务的父任务耗时由应用汇总为未完成子任务的剩余耗时，不能作为另一份独立预算编辑。

跨项目移动时，先暂停同步，把父任务及所有子任务行剪切到另一个已选择项目的 `tasks.md`，保留 ID 和原“笔记”链接，保存两个文件后恢复同步并点击“立即同步”。note 链接可以继续指向原位置。不要复制出相同 ID 的第二条任务。

## 5. 日期与时间

```markdown
- [ ] 独立任务 ⏳ 2026-10-03 📅 2026-10-05 [sp-planned-time:: 14:00] [sp-deadline-time:: 18:00] estimate [90min](<sp-estimate-minutes:: 90>) [sp-expected-finish:: 2026-10-03T16:00:00-07:00]
```

- 全天计划／截止只写日期，不进行时区转换。
- 具体计划／截止时间同时保留对应日期，使用 `HH:mm`，按面板时区解释。
- `sp-expected-finish` 是用户输入的预计完成时刻，必须包含时区偏移或 `Z`，不根据耗时自动计算。也可以在面板搜索任务后编辑并保存。
- 实际耗时 `sp-spent-minutes` 和完成时刻 `sp-completed-at` 为只读导出。
- 清除某个日期／字段时删除整个标记，不输入“明天”“未知”等文字。夏令时不存在的时刻会报告问题。

## 6. notes、引用和项目笔记

每个任务都有独立 notes 文件，包括 Inbox 中正文为空的任务。空文件的身份 YAML 保留，正文填写在 YAML 之后；YAML 不写入应用 notes。

notes 正文可引用 vault 内其他 Markdown：

```markdown
参考 [[资料/需求说明]]。
会议记录：![[资料/会议记录]]。
完整方案：[方案](资料/方案.md)。
```

完整引用正文会嵌入应用任务 notes 的 `sp-ref` 区块。改原笔记正文会传播到相关任务；改应用引用区块内的正文会写回源笔记。保留引用区块边界；源文件 YAML 保留。引用笔记中的复选框不会创建任务。

标题／block 引用只导出定位与只读摘录；不递归展开引用链，不复制附件。移除引用链接只解除关系，不删除源文件。引用重名时改为完整路径；多个任务副本有不同正文时，在问题列表选择要采用的版本。

**`project-notes/` 是什么？** 它导出 Super Productivity 原生项目层面的笔记，例如项目背景和资料，与单个任务的 notes 不同。默认关闭；开启“导出原生项目笔记（只读）”后才生成文件。第一版不把本地修改写回原生项目笔记。日常任务 notes 和引用同步不需要开启它。

## 7. 日历与历史归档

`calendar/index.md` 汇总有计划日期、截止日期或预计完成时刻的任务，每日文件链接到任务和 notes。任务日期在 `tasks.md` 或应用中修改；日历索引为只读。

每日笔记中的“下一步计划”等自由正文写在 `sp-generated` 区块之外，插件会保留。外部日历事件暂不同步。

“导出历史归档（只读）”默认关闭。开启后，原生历史任务按项目和完成月份导出到 `archive/YYYY-MM.md`，包括 notes 和子任务；归档文件不是任务编辑入口。

## 8. 删除与恢复

| 操作 | 结果 |
| --- | --- |
| 删除 `tasks.md` 中已关联任务行 | 保存快照，保留应用任务和原生 notes，加 `sync-removed` 标记并暂停该任务导出 |
| 删除父任务行 | 保留原生整个家庭，暂停对应关联 |
| 仅删除子任务行 | 记录子任务移除，标记父任务，不改变完成状态 |
| 在应用删除／归档任务 | 清理托管 note，不从旧 Markdown 自动重建任务 |
| 删除文件／目录 | 暂停相应绑定，原文与恢复信息保留 |
| 取消勾选项目 | 只停止同步，不删除内容 |

移除任务后，对应的托管 note 会先完整保存到 `.sp-sync/removed/`，再从项目目录清理。引用源笔记始终保留。

恢复步骤：

1. 在“已移除的同步关联”找到任务，点击“恢复关联”。
2. 如果任务已在应用删除／归档，先在应用恢复，再恢复关联。
3. 恢复同步并点击“立即同步”，检查 ID、notes 和父子关系。

恢复关联会还原缺失的 note。若应用 notes 在移除后已有修改，应用正文优先，移除副本仍保留。面板“查看备份”支持预览和恢复旧文件；恢复备份会暂停同步，确认内容后再恢复同步。

## 9. 自动同步与性能

默认应用变更延迟 **10 秒**同步，文件每 **30 秒**检查，Markdown 修改通常在约 40 秒内开始同步，之后还需要实际执行时间。完整补查间隔为 120 秒。连续修改会合并，点击“立即同步”会跳过等待。

频繁编辑或 vault 较大时，可以将“自动同步延迟”调整为 30／60 秒、“文件检查间隔”调整为 60／120 秒，保存设置后生效。提高间隔能减少文件检查和 Node 子进程调用。应用关闭、插件停用或同步暂停时不会运行同步。

## 10. 常见问题

| 现象 | 处理 |
| --- | --- |
| 按钮禁用 | 等后台连接；有未保存设置时先保存；已暂停时先恢复；选择至少一个项目 |
| 后台未连接／首次状态请求超时 | 确认安装 ZIP 并启用，关闭重开面板或点击“重新连接”；检查主程序 Node 权限对话框 |
| 目录确认按钮暂时点不了 | 等目录读取完成；可取消后重试 |
| `应用更新未通过读回验证` | 查看任务与差异字段；升级到 0.1.3 已修复父任务汇总耗时和子任务标签误判；其他字段不一致保留文件并暂停相关项目 |
| 没有生成 Inbox note | 勾选 Inbox，保存设置并立即同步；先处理该项目的问题列表 |
| 格式错误／重复 ID／第三层子任务 | 修复对应文件后重试；不要直接编辑 `.sp-sync/state.json` |
| note 或任务文件缺失 | 先恢复文件或关联；缺失 `tasks.md` 可在面板按提示重建 |
| 同字段两边都有修改 | 应用优先，旧文件保存为备份；不同字段可合并 |
| 引用重名／丢失／冲突 | 改用完整路径，恢复源文件，或在面板选择引用版本 |

第一版只支持单台设备写入同一 vault；网页／手机、附件复制、重复规则编辑及原生项目 notes 写回暂不支持。详细验证范围见 [验收记录](VALIDATION.md)。

AI 代改 Markdown 前，先提供同步目录的 `README.md` 或仓库 [AI 编辑指南](AI-GUIDE.md)。完整语法示例见 [格式示例](FORMAT-EXAMPLES.md)。
