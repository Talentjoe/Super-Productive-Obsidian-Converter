## 0.1.4 中英文支持

## 真实 19.1.0 桌面宿主

安装生成 ZIP，通过官方 iframe 和后台插件 API、官方 Node 执行桥实际运行，验证：

1. 首次选择 Inbox 后导出任务、独立 notes、README 和索引。
2. 在 Markdown 新建父子任务、标签、预计耗时、计划／截止具体时间及预计完成时刻，成功写入原生任务并生成稳定 ID。
3. 在应用修改引用正文，写回源笔记且保留 YAML；再改源笔记，传播回原生 notes。
4. 完成状态写回、重复同步无重复任务。
5. 仅删父任务行，保留原生整组与 notes；清理项目中的托管 note，完整副本保留；恢复关联后 note 和 ID 恢复。
6. 通过 `batchUpdateForProject` 提升子任务和重新关联。
7. 原生项目笔记默认不生成。

## 0.1.2 多项目、删除与性能回归

真实 19.1.0 宿主复现“应用更新未通过读回验证”：Markdown 父任务预计 90 分钟、子任务预计 30 分钟，应用自动将父任务耗时汇总为 30 分钟，旧插件仍比较 90 分钟并中止整轮导出。新版本遵循父任务原生剩余耗时汇总；独立任务字段继续严格验证。单项目读回失败会报告具体差异，其余无依赖项目继续。

在隔离实例同时选择 Inbox 和另一个项目，使用真实鼠标创建原生 Inbox 空 notes 任务、修改子任务分钟数、立即同步、通过原生 Delete task 确认删除。验证两个项目文件同时生成、Inbox note 身份 YAML、父子耗时及链接格式往返、删除后的托管 note 消失、恢复副本存在且旧任务不会复活。记录：`.tmp/host/multi-acceptance.json`、`.tmp/host/multi-fixed.png`。

后台默认延迟 10 秒、文件检查 30 秒、完整补查 120 秒；连续变化合并为一次同步，手动同步跳过等待。批量读写与不变内容跳过减少 Node 子进程调用；状态刷新降为可见面板每 10 秒，禁用控件使用普通指针。真实宿主控件测试还验证延迟／检查间隔保存并还原。Windows 系统忙碌光标不能保证完全消除。

运行 `npm run test:host:multi` 前，在隔离 vault 选择 Inbox 与另一个项目，并准备标题为“父子预计耗时回归”的父任务及一个耗时非零、尚未计时的子任务，先成功同步；测试在 45／50 分钟间切换以验证实际修改。不要指向个人数据。

## 0.1.1 界面故障与回归

真实宿主复现：进入子目录后立即点击“使用此文件夹”，确认按钮未等待 Node 读取完成，旧路径被确认后，迟到的结果重新打开弹窗。修复后，确认按钮在读取期间禁用；取消会结束前端等待并忽略迟到结果。异步目录读取和取消均增加了可控制延迟的安装包回归测试。

另外修复打包的字符串替换会解释 `$$` 等 JavaScript 字符的问题，保留 Solid 的事件绑定原文；首个状态请求使用 5 秒超时和独立连接状态，不再把后台初始化作为长达 120 秒的界面操作。提供重新连接、操作进度及 Node 权限提示。同步写入仍保留原有执行超时。

重新上传修复后的 ZIP 到真实 19.1.0 隔离实例，通过 `tests/host/ui.mjs` 验证（0.1.2／0.1.3 重跑）：

1. 文件夹打开、上一级、进入目录、确认和取消。
2. 项目勾选、导出开关、时区输入、延迟／检查间隔保存并还原，核对后台配置。
3. 恢复同步、立即同步、暂停及真实磁盘写入。
4. 预计完成时刻输入、保存、后台持久化核对及还原。
5. 备份列表、读取、预览和关闭。
6. 退出后重新打开面板，再次选择文件夹及取消。

这些操作使用 Playwright 的真实指针和键盘输入，没有调用 DOM `click()` 或强制点击，也没有用测试 RPC 替代后台写入。宿主切换动画结束后才定位 iframe；宿主闲置时间对话框用正常按钮关闭。先前的 0.1.0 桌面验收主要验证 API／文件流程，未充分覆盖此目录确认时序。

运行 `npm run test:host:ui`。必须使用本仓库 `.tmp/host/` 下的独立实例、调试端口 9229 和 `.tmp/host/vault`，并先安装当前 ZIP；测试会操作独立配置与任务补充时间，并以暂停同步结束。结果与截图保存在 `.tmp/host/ui-acceptance.json`、`.tmp/host/ui-fixed.png`。

原生 Node 权限确认在隔离测试进程中用测试桩选择 Allow；实际文件访问、任务 API 和同步逻辑没有替换为模拟实现。日常安装仍需用户在主程序原生权限对话框选择允许。

0.1.2／0.1.3 长时间验收在隔离进程中让闲置检测返回活跃，避免系统闲置弹窗干扰；原生删除确认仍使用真实按钮。测试桩不写入安装包。

真实测试发现并修复两项宿主差异：新任务默认插在顶部造成排序误报；较大状态触发 Windows `spawn ENAMETOOLONG`，现已用校验后原子提交的分块传输处理。

`tests/host/smoke.mjs` 可对已启动、已安装并配置插件的隔离测试实例重跑：调试端口 9229，应用必须来自本仓库 `.tmp/host/`，vault 必须为 `.tmp/host/vault`。运行 `npm run test:host`；它会创建独立验收任务、修改引用、删除／恢复关联，结束后暂停同步。不要指向个人 vault。

## 第一版边界

外部日历、附件复制、重复规则编辑、项目原生 notes 写回及多设备同时写入不在范围内。宿主任务接口不提供原子比较更新；插件通过写前读取和写后验证检测并发修改，文件侧使用哈希复核、备份及原子替换。单个笔记上限 4 MB，内部状态上限 64 MB；较大内容的同步耗时会增加。
